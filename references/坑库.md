# 技能开发踩坑库（精炼核查版）

AI Agent 技能开发实战避坑指南。标注【自动】的已由 `audit.py` 代码级拦截，标注【人工】的须在审查或自检时重点核对。

## 目录

- 一、上下文与架构类
- 二、质量门禁与验证失效类
- 三、环境与跨平台工程类
- 四、流程状态与交付安全类

## 一、上下文与架构类

1. **旧规则覆盖新规则**【人工】
   - **病症与根因**：重复参考文件存在，旧模板在后续阶段重新注入，导致输出呈现旧风格。
   - **对策**：同类规则确立唯一事实源，合并删重；禁止同一规则在多个参考文件中分头维护。

2. **嵌套技能误识别**【自动：FM001/SK004】
   - **病症与根因**：子目录内存在第二个 `SKILL.md`，导致宿主 Agent 误将其识别为主入口发生错乱。
   - **对策**：全仓库仅保留根目录唯一 `SKILL.md`，子内容重命名为 `README.md` 或事实卡。

3. **大文件一次性全量加载**【自动：SK002/SK005 / 人工】
   - **病症与根因**：`SKILL.md` >500 行或未分层，技能一触发便吃掉大半上下文窗口，导致注意力衰减。
   - **对策**：主文档只留路由器与按需引导，配置表与长参考下沉至 `references/`；多阶段流水线采用阶段卡按需加载。

4. **硬指令词通胀**【自动：TC002 / 人工】
   - **病症与根因**：全篇堆砌「必须/绝不/一律/禁止」，超出模型注意力遵循上限，导致模型跳步甚至视而不见。
   - **对策**：硬指令只留核心红线（安全/交付），操作性指导转为「情境触发（当...时，执行...）」。

5. **减负误拆按流程阶段拆成多技能**【人工】
   - **病症与根因**：为减负把单一工作流拆为多个技能接力，导致跨技能丢失状态、触发词竞争甚至中断。
   - **对策**：按「用户终极目标」拆分技能，不按内部流转步骤拆分；内部复杂度靠渐进式披露消化。

6. **文档命令与脚本参数漂移**【自动：LK002 / 人工】
   - **病症与根因**：脚本参数更新或流程收敛后，文档遗留过时的幽灵参数或孤儿命令，照抄即报错。
   - **对策**：文档内所有代码命令示例与脚本 `argparse` 参数严格对齐，废弃命令彻底删除。

## 二、质量门禁与验证失效类（高危）

7. **门名义存在实际放行**【自动：DY002 / 人工】
   - **病症与根因**：文档声明有严格门禁，但坏输入依然一路绿灯，因逻辑未触发或在死分支中。
   - **对策**：每道门必须配对负向用例（破坏必需文件或输入），断言坏样本必然触发 `rc!=0` 拦截。

8. **静默跳过（Silent Skip）**【自动：SF001/SF002】
   - **病症与根因**：依赖缺失或文件不存在时代码盲目 `continue` 或吞异常，产物缺失流程却报成功。
   - **对策**：跳过逻辑必须显式打出 WARN 日志；核心产物执行最终数量核验，禁止静默忽略。

9. **报告是旧的（掩盖真相）**【人工】
   - **病症与根因**：流程直接读取存量报告文件而非实时重跑，掩盖了代码修改后的新破坏。
   - **对策**：校验工具实时执行；关键交付前原样重跑，比对产物生成时间戳。

10. **退出码骗人**【自动：SF003】
    - **病症与根因**：脚本终端打印 `FAIL` 但退出码返回 `0`（或相反），导致外层调度误判通过。
    - **对策**：统一退出码语义：成功必须 `rc=0`，失败或拦截必须 `rc!=0`。

11. **正则门形态盲区**【自动：SEC002】
    - **病症与根因**：仅匹配单反斜杠路径（如 `C:\Users\` <!-- skill-doctor: allow -->），对 Python 转义双反斜杠或正斜杠变体放行。
    - **对策**：正则必须覆盖多形态（正斜杠、反斜杠、转义斜杠）；负向夹具覆盖全部常见写法。

## 三、环境与跨平台工程类

12. **PowerShell 重定向写出 UTF-16**【自动：EN003】
    - **病症与根因**：PowerShell `>` 或 `Tee-Object` 默认输出 UTF-16 包含 BOM，导致后续脚本读不到。
    - **对策**：重定向显式追加 `| Out-File -Encoding utf8`；跨工具传递产物统一强制 UTF-8。

13. **文件时间戳精度陷阱**【人工】
    - **病症与根因**：快速写文件后利用时间戳比对新旧，因文件系统时间分辨率限制导致误判。
    - **对策**：测试夹具显式设定递增时间戳；生产判断采用版本号或单向哈希比对。

14. **外部服务网络路径分裂**【人工】
    - **病症与根因**：国外 API 需代理、国内 API 需直连，全局代理一刀切导致部分请求挂死。
    - **对策**：网络调用模块化，支持按域名分流或独立配置代理参数。

15. **资源文件字节级污染致宿主拒读**【自动：EN006】
    - **病症与根因**：Markdown 或文本资源文件中混入控制字符或 `\x00` 空字节，导致宿主拒绝解析。
    - **对策**：所有文本资产入库前确保纯净 UTF-8 编码且无不可见控制字符。

16. **Bash 脚本混入 CRLF 换行**【自动：PL001】
    - **病症与根因**：在 Windows 下编辑 Shell 脚本生成 `\r\n`，在 Linux CI 执行报 `command not found: set`。
    - **对策**：Git 配置 `.gitattributes` 强制 `*.sh text eol=lf`；CI 中校验换行符。

## 四、流程状态与交付安全类

17. **多处口径打架**【自动：CK001】
    - **病症与根因**：主文档、脚本和参考文档对同一参数（如字数上限、重试次数）各自定义且不一致。
    - **对策**：全局统一基准，建立唯一口径源；`audit.py` 自动化检测跨文件数字冲突。

18. **禁止示例污染实际输出**【人工】
    - **病症与根因**：Prompt 中提供的 Few-Shot 示例实体，在真实任务中被模型机械照抄进最终成果。
    - **对策**：示例使用虚构标记占位，Prompt 明确声明“示例仅作格式参考，严禁原样输出示例实体”。

19. **交付包含开发私货与会话标记**【自动：SEC002/SEC005】
    - **病症与根因**：将本地绝对路径（`C:\Users\...` <!-- skill-doctor: allow -->）、调试临时报告（`audit-report.txt`）提交进仓库。
    - **对策**：绝对路径改用相对路径或占位符；发版前物理清理所有审计报告与临时中间件。

20. **只信返回码不信内容**【人工】
    - **病症与根因**：外部 API 成功返回 HTTP 200，但响应 Body 为 `{"code": 500, "msg": "failed"}`，被误判为成功。
    - **对策**：校验必须结合 HTTP 状态码与响应体业务字段双重断言。

21. **弱引用措辞导致 References 不被阅读**【自动：LK005】
    - **病症与根因**：使用“可参考/详见/建议阅读”，大模型在执行时直接忽略，导致关键知识未加载。
    - **对策**：消灭“建议”，改为明确情境触发词：“当 [遇到某情况] 时，必读/先读 [某文件]”。

22. **回退路径只活在脚本里未暴露给用户**【人工】
    - **病症与根因**：执行了破坏性操作后，回滚命令仅写在内部注释中，用户故障时求助无门。
    - **对策**：高危治理必须随报告直接呈现用户可执行的单行回退命令。

23. **破坏操作未与只读诊断解耦**【人工 / SEI Safety】
    - **病症与根因**：排查脚本暗含修改、删除或重启逻辑，在体检阶段擅自改动用户系统。
    - **对策**：坚守 Zero-Mutation 原则；排查 100% 只读，治理动作必须经用户明确授权后方可执行。
