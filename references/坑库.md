## 一、上下文与加载类

### 1. 旧规则覆盖新规则
- **现象**：主规范已改，输出仍呈旧风格/旧结构
- **根因**：重复参考文件存在，旧模板在后续阶段重新注入
- **修复**：确定每类规则唯一来源，合并删重
- **预防**：回归扫描旧文件名与冲突关键词
- **检查**：人工——同名规则在多个文件出现即黄牌

### 2. 嵌套技能误识别
- **现象**：子目录里的 SKILL.md 被宿主当成主入口，行为错乱
- **根因**：技能目录树里存在第二个 SKILL.md
- **修复**：子内容改名（如 README.md / 参考卡.md）
- **预防**：结构约定全树唯一入口
- **检查**：自动——FM001/SK004

### 3. 大文件一次性全量加载
- **现象**：技能触发后上下文被吃掉大半，任务质量下降
- **根因**：SKILL.md 超 500 行或参考无分层
- **修复**：拆分到 references/，SKILL.md 只留路由
- **预防**：写之前估算 token 成本
- **检查**：自动——SK002/SK003

## 二、门的失效类（最危险）

### 4. 门名义存在，实际放行
- **现象**：文档声称有校验，坏输入却一路通过
- **根因**：校验逻辑从未被触发（条件写错/在死代码里），或异常被吞
- **修复**：每道门配负向用例，放行了该拦的东西就是坏门
- **预防**：新增门必须同时新增"该 FAIL 的夹具"进 selftest
- **检查**：人工——audit.py 负向抽查（方法论步骤4）

### 5. 静默跳过
- **现象**：日志里一行 skipped，产物缺失，流程却显示成功
- **根因**：可选依赖缺失/文件找不到时代码 continue 而非报错
- **修复**：跳过必须升级为 WARN 日志 + 最终产物核对数量
- **预防**："figures=N 与清单数量一致"类终检
- **检查**：自动——SF001/SF002；人工——终检逻辑是否存在

### 6. 报告是旧的，真相被掩盖
- **现象**：校验报告显示 PASS，但那是改代码之前的旧报告
- **根因**：流程读报告文件而非重跑校验
- **修复**：关键门在交付前原样重跑一遍
- **预防**：报告带时间戳，交付门比对时间戳新鲜度
- **检查**：人工——比对报告 mtime 与源码 mtime

### 7. 退出码骗人
- **现象**：脚本打印 FAIL 但 rc=0（或反之），上游调度全乱
- **根因**：退出码与文本结论脱节
- **修复**：约定 FAIL 必须 rc≠0，调度只认 rc
- **预防**：selftest 里加 rc 语义断言
- **检查**：自动——SF003

### 24. 正则门只认一种编码形态（2026-08-19，源自 skill-doctor 自审负向抽查）
- **现象**：SEC002 检测个人路径，单反斜杠 `C:\Users\` 能拦，Python 源码最常见的转义双反斜杠与正斜杠变体静默放行 <!-- skill-doctor: allow（坑描述自身示例） -->
- **根因**：正则按单一写法匹配，而同一违规在源码里存在转义、正斜杠等多种编码形态
- **修复**：字符类同时接受正斜杠与反斜杠（含转义双反斜杠），全部形态一网打尽；负向夹具须覆盖每种形态
- **预防**：写路径/字符串类检测正则时，先枚举同一违规的全部常见编码写法再落笔；新增门与负向夹具同生（坑 4 预防纪律的细化）
- **检查**：自动——SEC002（正则已扩形态）；负向夹具见 scripts/selftest.py LEAK_FORMS

## 三、环境类（Windows 重灾区）

### 8. PowerShell 重定向写出 UTF-16
- **现象**：检查器输出 PASS，回读脚本报读不到内容
- **根因**：`>` / `Tee-Object` 默认 UTF-16
- **修复**：显式 `| Out-File -Encoding utf8`
- **预防**：所有交给脚本回读的文本产物显式 UTF-8
- **检查**：自动——EN003

### 9. 文件时间戳精度陷阱
- **现象**：快速连续写文件后，"A 新于 B"判断误杀或漏杀
- **根因**：Windows mtime 粒度 1ms（FAT 更粗），快写时间戳相同
- **修复**：测试夹具显式设递增 mtime；生产判断用 ≥ 或留间隔
- **预防**：涉及时间戳的测试不依赖文件系统精度
- **检查**：人工——测试里是否有 utime 显式设时

### 10. 外部服务网络路径分裂
- **现象**：生图走代理成功、上传直连失败，或反之
- **根因**：多外部服务对代理需求不同（被墙的要梯子，国内 API 要直连），全局代理一刀切
- **修复**：按域名分流；下载与上传分路重试
- **预防**：外部调用统一入口脚本，代理可配且默认按需
- **检查**：人工——外部调用是否集中管理

### 11. 一次性数据当持久标识
- **现象**：缓存了某 API 返回的 ID，几小时后用它查询报无效
- **根因**：部分平台的 media_id 类标识与资源存续期绑定
- **修复**：用前重新列表确认，不假设可用
- **预防**：易失效数据不落长期缓存
- **检查**：人工——搜缓存 JSON 里是否有时效字段未校验

## 四、流程状态类

### 12. 上游改了，下游还是旧的
- **现象**：标题/正文/图互相不一致，交付的是缝合怪
- **根因**：没有按最早受影响阶段回退，或手改状态文件绕过守卫
- **修复**：回滚到受影响最早阶段，向下重跑
- **预防**：产物带阶段与时间戳；上游改动触发下游失效
- **检查**：自动——时间戳新鲜度类检查（如被审技能有此机制）

### 13. 校验发现越晚，返工越大
- **现象**：终审才发现密度不够，S3/S4/S5 全部重跑
- **根因**：关键校验只挂在流程末端
- **修复**：校验前移到产出该属性的最早阶段
- **预防**：新属性新门，先问"这个检查最早能在哪做"
- **检查**：人工——对照流程图看门的位置

### 14. 多处口径打架
- **现象**：文档说上限 5 个，脚本数到 4 就报错；速查卡与主文档例外规则不一致 <!-- skill-doctor: allow（坑描述自身示例） -->
- **根因**：同一阈值散落多处，改一处忘其余
- **修复**：抽公共常量或单一来源文件，其余指针引用
- **预防**：一致性 lint（同阈值多处出现必须逐条对齐）
- **检查**：自动——CK001（md 间限定词+量词阈值比对，2026-08-20）；脚本常量与文档口径仍需人工比对

## 五、生成内容类

### 15. 禁止示例污染输出
- **现象**：规范里的反例措辞出现在正式产出里
- **根因**：反例进入上下文形成高显著度提示
- **修复**：改正向质量标准；词表外置给确定性脚本
- **预防**：技能本体不嵌大段反例
- **检查**：人工——搜反例章节

### 16. 装饰符被当普通留白
- **现象**：分隔符满天飞，结构信号被稀释
- **根因**：一个函数承担两种语义（章节边界/视觉呼吸）
- **修复**：语义拆开，装饰符仅限特定位置
- **预防**：编辑器拒绝正文装饰符；校验数分隔符数=结构数-1
- **检查**：人工——分隔符计数逻辑

## 六、交付类

### 17. 交付包含私货
- **现象**：交付包里出现本机绝对路径、临时文件、密钥
- **根因**：直接打包工作目录
- **修复**：白名单交付目录，交付前扫描
- **预防**：临时目录验证交付包
- **检查**：自动——SEC001/SEC002

### 18. 只信返回码不信内容
- **现象**：上传 API 返回成功，实际草稿缺标题/封面
- **根因**：把"API 成功"当"内容正确"
- **修复**：交付后回读校验（内容级，非状态级）
- **预防**：回读是交付流程的一部分，不是可选项
- **检查**：人工——交付后有无回读步骤

## 七、frontmatter 与触发类（2026-08 补充，源自生态调研）

### 19. name 含保留字 / description 含 XML 尖括号被拒收
- **现象**：技能上架 Claude.ai / 插件市场失败，或触发异常
- **根因**：name 含 anthropic/claude 保留字、description 含 `<` `>` 尖括号（有注入系统提示风险），平台硬拒
- **修复**：改 name 去保留字；description 去尖括号（如写"小于/大于"或用代码块包裹）
- **预防**：命名与描述不出现保留字与尖括号
- **检查**：自动——FM006/FM007

### 20. description 超预算被静默截断
- **现象**：手动测试能触发，真实会话 agent 完全无视该技能
- **根因**：description 总预算超限（社区实测 ~15k 字符 / ~4k tokens），超限部分被**静默截断**且无任何报错
- **修复**：description 压短（30 词路由器式写法，只留触发词）；检查器统计 Σ description 预算
- **预防**：SKILL.md 正文与 description 都做 token 预算估算
- **检查**：自动——SK005（正文 token）；人工——description 总预算

### 21. YAML 被格式化器重排破坏
- **现象**：单独解析正常，Prettier 等格式化后技能加载失败
- **根因**：block scalar（`>`/`|`）多行描述易被重排破坏；frontmatter YAML 错时不报错但失去触发匹配（静默失效）
- **修复**：description 单行 + `# prettier-ignore`；或显式引号包裹
- **预防**：frontmatter 保持简单标量，不用多行块
- **检查**：人工——frontmatter 是否用了 block scalar

### 22. references/ 文件不会自动加载
- **现象**：写了 references/ 但 agent 从不读，效果与预期不符
- **根因**：辅助文件不会自动扫描，必须在 SKILL.md 显式链接才会按需加载
- **修复**：SKILL.md 显式引用每个 references 文件（带使用时机）
- **预防**：新增 references 文件必须同步在 SKILL.md 加链接
- **检查**：自动——LK004（孤儿文件）

### 23. 脚本交互提示挂死 agent
- **现象**：agent 调用脚本后无响应（挂死），或静默失败
- **根因**：脚本含 `input()` 交互提示，agent 是非交互 shell，无人应答
- **修复**：一切参数走 CLI flag/env/stdin；删除 input()
- **预防**：脚本接口全参数化；提供 `--help`
- **检查**：自动——SF006

## 八、审查器自身类（2026-08-20，源自用 skill-doctor 审 yao-meta-skill）

### 25. 回归入口只认一种命名
- **现象**：被审技能明明有 85 个 pytest 测试文件，审查器仍报"未找到 selftest，技能不可回归"FAIL
- **根因**：检查器把自己偏好的命名（selftest.py）当成唯一惯例，没考虑 pytest/tests/、Makefile test 等生态主流布局
- **修复**：入口识别按优先级扩展为 selftest 命名 > tests/ 目录（≥1 个测试 .py）> Makefile test 目标；非 selftest 入口不自动实跑，INFO 提示人工执行
- **预防**：检查器对生态内有多流派惯例的东西（命名、布局、编码），先枚举主流形态再落笔（坑 24 同理：同一违规的多形态都要认）
- **检查**：自动——DY001；负向夹具见 scripts/selftest.py pytest_layout 夹具

### 26. 夹具假密钥当真泄露
- **现象**：tests/ 目录里故意写的违规样本（假 key、假 token）被按硬编码密钥报 FAIL，误伤整个审查结论
- **根因**：安全扫描不区分"生产代码里的真密钥"与"测试夹具里的故意违规样本"——后者正是负向用例的原料，拦它等于惩罚做对的事
- **修复**：按路径上下文分流——tests/fixtures/examples/evals 内的密钥样式命中降级 WARN（人工确认为故意样本即可放行），主代码命中保持 FAIL
- **预防**：安全类检查必须考虑夹具上下文；夹具与生产同形态不同语义的东西都要分流
- **检查**：自动——SEC001 夹具分流；负向夹具见 scripts/selftest.py fixture_leak 夹具

## 九、引导与发现类（2026-08-22，源自 agentskills.io 规范调研）

### 27. 弱引用措辞导致 references 不被读
- **现象**：SKILL.md 里写「详见 xxx.md」「有问题可参考 xxx」，执行 AI 从不主动打开——积累的参考资产被浪费，审查/执行退化为"只看 SKILL.md 就下结论"
- **根因**：Agent Skills 规范规定 references 按需加载（loaded only when required），是否读取取决于 SKILL.md 的引导措辞；"详见/可参考"没有给出**读取时机**和**为什么值得读**，模型不会自觉补读
- **修复**：每个 reference 链接都配「何时读 + 为什么」——把读取动作内嵌到工作流的具体步骤里（如"步骤 4 负向抽查前，必读方法论负向用例节：构造方法在里面"）；官方 skill-creator 措辞哲学是解释价值（theory of mind）而非堆 MUST
- **预防**：写 SKILL.md 时逐个 reference 自问"模型在哪个瞬间会需要它？"并把那个瞬间写进对应步骤；大文件（>300 行）加目录
- **检查**：已并入 audit.py——LK005 自动检测（references 被提及但所有提及行均无强引导措辞时给 WARN）；出处：agentskills.io/specification（progressive disclosure 三层）+ anthropics/skills 官方 skill-creator 第 97/139 行

### 28. CK001 数字对撞的两类误报
- **现象**：CK001 报"阈值口径打架"，人工读原文后确认两处均为误报：① **引文数字**——正文引用已废除的历史口径且自带废除说明（如"历史'超过 6 张才 WARN'……已废除"），被当现行阈值；② **跨对象数字**——不同约束对象的数值凑对（如引用块"全文最多 2 个" vs H2"上限 3 个"、PAT"最多 50 个" vs 扫描"超过 200 个"）
- **根因**：CK001 按"数字相同+文件不同"配对，不识别语义语境（引文标记、废除声明、度量对象不同）
- **修复（被审技能侧）**：确认误报后在对应行加 `<!-- skill-doctor: allow CK001 +理由 -->` 豁免
- **预防**：写文档时历史口径引文尽量改述而非原样保留数字；同一数字用于不同对象时加对象限定词
- **检查**：半自动——CK001 报警后必须人工读原文定性，检测器自动消歧留待后续版本
