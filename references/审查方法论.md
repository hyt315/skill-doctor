## 一、四大全景技能形态专属审查引擎（Step 0）

在进入详细检查前，先判定被审技能的所属架构形态，并启用对应的专属体检重点：

| 技能形态 | 典型特征 | 专属体检核心重点 |
|---|---|---|
| **1. 纯提示词 / 知识库型** | 零 scripts，仅 `SKILL.md` + `references/` | Prompt 膨胀率、硬指令密度（`TC002` ≤15 处）、引用单层直达、避免 System Prompt 挤占 |
| **2. CLI / 脚本增强型** | 带 `scripts/`（Python / Bash / Node） | 跨平台路径（`PL002`）、Windows CRLF/LF 换行（`PL001`）、`set -euo pipefail`（`EN005`）、退出码语义（`SF003`）、零依赖声明（`EN004`） |
| **3. MCP / 协议端型** | 含 MCP JSON 配置或 API 桥接 | Tool 定义与 Schema 规范、`stdio`/`sse` 模式、环境变量安全读取（`SEC003`）、Token 与敏感字段脱敏 |
| **4. 多阶段流水线型** | 含状态机（如 `stages/sN.md`、状态文件） | 路由器+阶段卡模式、阶段自证逻辑、状态文件落盘机制、回滚与中途断点恢复能力 |

## 二、四件套详解

### 1. 静态口径对齐
对齐三方：SKILL.md 承诺的 ↔ scripts 实现的 ↔ references 描述的。

操作：`audit.py` 跑出结构/引用/资产/静默失效/安全/脚本/跨平台各类结果后，人工补两类脚本抓不到的：
- **阈值口径**：数字类规则全树搜索（上限 N 个、字数 ≥X），多处出现逐条比对（`CK001`）
- **流程闭环**：SKILL.md 画的流程图每个箭头都有实现，每阶段产物都有消费者

### 2. 动态实跑
把被审技能自己声称的验证真跑一遍。

操作要点：
- 跑前记录环境（Python 版本、OS、关键依赖版本）——环境性缺陷的复现依赖
- 优先跑 selftest；没有 selftest 本身就是重要发现（记 FAIL：技能不可回归，`DY001`）
- 跑前确认命令作用域（临时目录/只读），避免污染被审技能目录
- 结论只认：退出码 + 末行 RESULT + 产物文件三者一致（`DY003`）
- **selftest 输出约定**：成功收尾打印 `SELFTEST PASS (N checks)`，失败打印 `SELFTEST FAIL` 并以 rc=1 退出。

### 3. 负向用例
每道被审技能声称的"硬门"，构造该 FAIL 的输入验证它真拦。

构造模式（按门类型选）：
| 门类型 | 破坏夹具 |
| --- | --- |
| 文件齐全门 | 抽掉一个必需产物，重跑门 |
| 内容质量门 | 构造超限样本（超长段落/超量元素） |
| 一致性门 | 只改三处中的一处（另两处留旧值） |
| 新鲜度门 | touch 上游文件不重跑下游 |
| 回读门 | 提交后篡改一处内容看能否发现 |

验证标准：门必须 FAIL 且 rc≠0。放行了 = 静默失效，最高优先级 FAIL。

### 4. 坑库对照
`坑库.md` 逐条过 40+ 条踩坑。标"自动"的看 audit.py 输出即可，标"人工"的现场判断。发现新坑当场回写坑库。

## 三、触发用例四分类（借力 OpenAI eval）

评估技能触发可靠性时（是否该激活/是否误激活），构造四类 prompt：

| 类型 | 目的 | 构造 |
| --- | --- | --- |
| 显式 | 点名技能也能触发 | 直接写技能名 |
| 隐式 | 不点名但场景完全匹配 | 只描述任务场景 |
| 情境 | 带噪声的真实请求 | 场景+无关上下文 |
| 负向 | 相邻请求不得触发 | 只改既有产物的请求（易误触发点） |

## 四、成功四目标检查（OpenAI Evals 扩展）

| 目标 | 问什么 | 检查示例 |
|---|---|---|
| **Outcome 结果** | 任务完成了吗 | 产物存在、应用可运行、关键文件已生成 |
| **Process 过程** | 步骤走对了吗 | skill 被调用、工具顺序符合预期、无跳步 |
| **Style 风格** | 输出符合约定吗 | 命名/结构/格式符合 SKILL.md 承诺 |
| **Efficiency 效率** | 有没有浪费 | 命令循环检测、token 用量在合理范围 |

## 五、审查报告格式与导出选项

### 1. 标准文本报告（`audit-report.txt`）
```text
技能审查报告：<技能名> <日期>
环境：Python x.x / <OS> / 架构形态：<四大形态之一>

检查结果：
OK   [FM001] SKILL.md 存在
WARN [PL001] bash 脚本含 CRLF 换行（证据：scripts/test.sh）
FAIL [SEC001] 发现硬编码密钥（证据：scripts/app.py:L12）

共 N 项，通过 x，WARN y，FAIL z
RESULT PASS|FAIL
```

### 2. CI 与自动化导出参数
- `python scripts/audit.py <path> --json`：输出机器可读 JSON，供 CI 脚本断言与看板消费；
- `python scripts/audit.py <path> --markdown`：生成标准 GitHub Markdown 表格，可直接贴入 PR 或 Issue。

## 六、分级修复决策与自愈建议

| 场景 | 策略 |
|---|---|
| **单项问题** | 按该项最小修复路径，修完只重跑受影响检查 |
| **多项并存** | 找最深根因（如"文档脚本口径打架+报告过期"常因缺少自动化 lint），从根因修 |
| **跨平台失效** | 采用 `dos2unix` 或 Python 规范化换行，路径采用 `Path` 封装 |
| **负向用例发现的新失效** | 修复 + 坑库回写 + 同类门全查一遍 |

## 七、大改安全验证流程（治疗流程）

对技能做结构性大改时按此流程，防止「治好了 A 弄坏了 B」：

1. **沙箱先行**：完整复制技能到独立临时目录，一切改动只在沙箱做；
2. **基线回归**：改动前在沙箱跑一遍技能自身的全部回归，记录基线；
3. **内容锚点对账**：结构性搬迁前后，用功能锚点词清单 grep 新旧组合逐一核对；
4. **三重回归 + 差分对比**：改后重跑全部回归须与基线同绿；
5. **全链演练**：跑一篇最小真实任务走完全流程；
6. **逐字节确认后合并**：确认无误后才同步回正式目录；
7. **病例归档**：改造中发现的新病型按坑库格式回写。
