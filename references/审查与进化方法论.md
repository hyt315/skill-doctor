## 一、五大架构形态判定与自适应考量

在审查或进化启动前（Step 0），首先判定被测技能所属的架构形态，因材施教启用专属重点，**坚决不搞一刀切，坚决不强塞无意义空脚本**：

| 技能形态 | 典型特征 | 专属审查重点 | 进化重点与免测策略 |
|---|---|---|---|
| **1. 纯提示词 / 认知指导型 (PROMPT)** | 零脚本，仅 `SKILL.md` + `references/` + `evals/` | 严查 Prompt 膨胀率与硬指令词密度（`TC002` ≤15 处）；输出 Schema 结构化约束；反幻觉负向边界 | **绝不强塞空脚本！** 工具化考核自适应切换为「输出 Schema + Few-Shot」，回归验证以 `evals/` 评测集与反例用例为主 |
| **2. CLI / 工具增强型 (CLI)** | 带 `scripts/`（Python / PowerShell / Bash） | 跨平台路径（`PL002`）、LF 换行（`PL001`）、`set -euo pipefail`（`EN005`）、退出码语义（`SF003`）、零外部依赖（`EN004`） | 纯标准库实现；支持 `--json` 机读与控制台只读；健全 `selftest.py` 与破坏夹具 |
| **3. MCP / 协议生态端型 (MCP)** | 含 MCP JSON 配置或 API 桥接 | Tool 定义与 Schema 规范；`stdio`/`sse` 模式；环境变量安全读取（`SEC003`）；Token 凭据脱敏 | 接口健壮性、超时熔断与错误码标准化 |
| **4. 多阶段流水线型 (PIPELINE)** | 含状态机（如 `stages/sN.md`、状态文件） | 路由器+阶段卡模式；阶段自证逻辑；状态落盘机制；断点恢复与回滚能力 | 状态持久化、幂等执行与死循环防御 |
| **5. 复合型 (HYBRID)** | 脚本工具 + 深度知识库/评测集复合体 | 兼顾确定性脚本执行（只读无损）与提示词认知工程，要求 AST 解析与破坏夹具双闭环 | 全要素工程化：脚本工具化 + 知识事实卡 + 自动化回归套件 |

## 二、全周期四阶段闭环工程流水线

```text
[阶段 1: 现状诊断] ──> [阶段 2: 方案与深水区挖掘] ──> [阶段 3: 处方施工与结构治理] ──> [阶段 4: 闭环回归与终审]
 (静态40+ / SEI)         (四维RFC/工单锁)              (消灭弱引用/物料锁/脚手架)        (全绿断言 / 零污染)
```

### 阶段 1：全方位现状诊断（只读体检）
- **审查四件套实操**：
  - *静态口径对齐*：`audit.py` 覆盖 40+ 规则，重点排查弱引用（`LK005`）、空头支票跳步（`SF007`）与口径一致性（`CK001`）；
  - *动态实跑*：`audit.py --dynamic` 核对退出码 (rc=0) 与末行 RESULT 一致性；
  - *负向破坏夹具（DY002）*：对关键硬门故意构造坏样本抽查拦截能力（放行即判静默失效）；
  - *坑库对照*：逐条核验 `references/坑库.md` 中的 50+ 项实战踩坑。
- **环节公开与官方检测报告交付**：
  - 严禁暗箱操作或仅回复简易通过！必须执行 `python scripts/audit.py <目标目录> --report`，在会话中完整公开输出五大系统检测明细与证据链；
  - 若用户需要存档，可通过 `--report-file <路径>` 导出独立的 Markdown 质量检测报告；
- **只读出口断点**：若用户仅要求“体检/找茬/回归”，交付结构化检测报告与处方后，流程正常结案。

### 阶段 2：方案设计与深水区挖掘
- **处方清单聚合**：`evolve.py --plan` 自动联动阶段 1 查出的静态缺陷（`LK005`/`SF007`），生成待修清单；
- **十二组多角度立体联网检索矩阵**：通过 `evolve.py --research-plan` 落盘 `.doctor/research-task.json` 任务单锁，执行立体挖掘：
  - *维度 1：GitHub 同类开源技能标杆 (Peer Agent Skills) [3 组]*：Prompt 架构、触发与反幻觉边界、多文件资产沉淀；
  - *维度 2：GitHub 顶级开源工程实现 (Top Domain OSS) [3 组]*：明星项目架构、原生 CLI 参数与机读设计、专家排查工具命令；
  - *维度 3：底层原理与权威规范 (RFC & Specs) [3 组]*：IETF RFC 官方协议、行业性能与超时基线、状态机与标准错误码；
  - *维度 4：生产级故障、隐蔽踩坑与边缘冷门探索池 (Killer Pitfalls & Fringe Cases) [3 组]*：生产重大事故复盘、并发死锁与静默失效、以及【冷门长尾探索池】（双栈、代理回路、多网卡跃点、跨平台特异性隐患）。
- **三层立体检索与深度穿透执行准则（Deep Reading Mandate）**：
  - *广度扇出*：不仅搜直接相关的关键词，更广泛探索边缘冷门长尾，绝不因看似不直接相关而预先过滤；
  - *深度穿透*：严禁走马观花仅看搜索结果摘要！强制挑选 Top 3~5 篇权威 RFC 规范或顶级开源代码，调用网页抓取工具深入精读全文；
  - *过程 100% 透明公开*：在会话中必须公开披露本次检索的所有 Query、深入阅读的来源 URL 列表、以及从冷门长尾资料中提炼出的实战避坑见解；
  - *物料探针与语法门禁*：代码片段必须经 `ast.parse` 或语法解析验证，严防不可用或陈旧代码入库。
- **三级弹性优雅降级策略（Adaptive Fallback）**：
  - *Tier 1（全网在线）*：联网完整检索 12 组立体矩阵并深入精读；
  - *Tier 2（定向白名单）*：弱网环境下定向检索 GitHub 仓库；
  - *Tier 3（离线启发式降级）*：无网或搜索受限时，执行 `python scripts/evolve.py <目标目录> --offline-fallback`，调用内置专家知识库一键生成基础避坑库与事实卡，任务锁标记为 `OFFLINE_HEURISTIC_FALLBACK`，解除门禁阻断，确保流水线永不卡死。

### 阶段 3：处方施工与结构治理（核心治理）
#### (1) 弱引用改造模式：行内动作指令（Inline Action Directives）
- **反例（弱引用/易被 AI 忽略）**：
  ```markdown
  ### 阶段 1：排查
  执行诊断排查。如果需要，可参考 `references/故障手册.md`。详见官方规范。
  ```
- **正例（行内动作化/不可绕过）**：
  ```markdown
  ### 阶段 1：排查
  - [ ] 1. 运行核心诊断命令：
        👉 动作：执行 `python scripts/diag.py --check`
  - [ ] 2. 匹配并分析深水区故障：
        👉 动作：读取 `references/故障手册.md`，比对当前错误码对应的排查对策
  ```

#### (2) 空头支票改造模式：硬锁产物门禁（Artifact Gating）
- **反例（声明式空头支票/易脑补跳步）**：
  ```python
  # 仅打印建议或要求大模型自律，大模型容易在回复中假装执行而跳步
  def plan_research():
      print("请务必使用 search_web 搜索以下关键词并阅读权威规范：...")
  ```
- **正例（工单落盘 + 强制机器门禁）**：
  ```python
  # 生成必须落盘的任务锁工单，后续阶段强行阻断未完成任务
  def plan_research(output_dir):
      task_lock = {
          "status": "AWAITING_SEARCH_AND_PITFALLS",
          "required_artifacts": ["references/domain-pitfalls.md"],
          "queries": ["..."]
      }
      lock_file = Path(output_dir) / ".doctor" / "research-task.json"
      lock_file.parent.mkdir(parents=True, exist_ok=True)
      lock_file.write_text(json.dumps(task_lock, indent=2, ensure_ascii=False), encoding="utf-8")
      print(f"🔒 已生成硬锁任务工单：{lock_file}。后置步骤必须检测产物落盘方可解锁。")
  ```

#### (3) 只读与治理解耦铁律 (Zero-Mutation)
- **只读默认**：体检、诊断、审查全流程 100% 只读，严禁擅自修改文件、配置或服务；
- **治理解耦与显式授权**：修复动作独立拆分，提供 Dry-Run 预检清单与秒级回滚命令，**必须经用户明确授权后手动执行**。

#### (4) 大改安全防退化 7 步法
1. 沙箱先行 ➔ 2. 基线回归 ➔ 3. 内容锚点对账 ➔ 4. 三重回归+差分对比 ➔ 5. 全链演练 ➔ 6. 逐字节确认合并 ➔ 7. 病例归档至坑库。

### 阶段 4：闭环回归与终审验收
- **静态 AST 安全解析**：静态扫描危险调用（裸 `eval`、宽捕获吞异常）与跨平台路径；
- **终审全绿断言**：重新跑通阶段 1 诊断（`audit.py --dynamic` 与 `evolve.py --analyze`），确保静态 0 FAIL，SEI $\ge 85$；
- **工程卫生与纯粹日志**：测试副产物（`audit-report.txt` 等）发版前物理清除；Commit 与 Release Notes 严格只记录功能优化与缺陷修复，严禁混入审查元过程。

## 三、形态自适应的技能进化指数（SEI）评估矩阵

SEI 为 100 分量化成熟度模型，由 `scripts/evolve.py` 自动计算并自适应加权：

| 评估维度 | 满分 | CLI / HYBRID / MCP / PIPELINE 考核重点 | 纯提示词型 (PROMPT) 自适应考核重点 |
|---|---|---|---|
| **1. 架构完备度** | 20 | `SKILL.md` (5) + `references/` (5) + `scripts/` (5) + `tests/` (5) | `SKILL.md` (10) + `references/` (5) + `evals/` (5)（零脚本不扣分） |
| **2. 工具/指令工程** | 20 | 原生脚本无第三方依赖 (10) + 机读输出支持 (10) | 结构化输出 Schema (10) + Few-Shot (5) + 反幻觉负向边界 (5) |
| **3. 事实卡工程** | 20 | 标准分层事实卡表格（检查项、实测值、基线、判定） (20) | 标准分层事实卡表格（检查项、实测值、基线、判定） (20) |
| **4. 安全与只读** | 20 | Zero-Mutation 只读优先 (10) + 治理须用户显式授权 (10) | Zero-Mutation 无破坏声明 (10) + 建议须用户确认/免责边界 (10) |
| **5. 自动化验证** | 20 | 回归套件 (10) + 破坏性负向夹具 (5) + 语法 AST 校验 (5) | `evals/` 评测集 (10) + 对抗性输入/反例边界测试样本 (10) |

### 成熟度评级
- **成熟级 (85 - 100 分)**：工业级成熟技能，形态契合度高，工具/提示词与自测闭环完备；
- **进阶级 (60 - 84 分)**：框架健全，需补强破坏负向夹具、深水区踩坑库或量化事实卡；
- **雏升级 (< 60 分)**：结构缺失严重，缺乏约束、评测集或基础多文件解耦。

### 标准技能全方位体检与质量检测报告规范（Inspection Report Specification）

严禁“黑盒暗箱体检”或“仅回复一句空洞的 OK”。阶段 1 交付或通过 `audit.py --report` 必须输出五大标准板块的 Markdown 检测报告：
1. **技能基本档案与体质画像**：技能名称、版本号、架构形态识别结果、代码行数与估算 Tokens、触发描述长度、硬指令词密度；
2. **综合健康指数与体检结论 (Executive Summary)**：健康评级（🟢 工业级成熟 / 🟡 进阶亚健康 / 🔴 雏升阻塞）、L1 静态合规率、L2 动态实跑与负向拦截判定、L3 SEI 持续演进量化雷达打分；
3. **五大核心系统体检明细与证据链 (Detailed Findings)**：
   - 基础元数据与触发规范 (FM001~FM008, SK001, SK004)
   - 引用链路与动作闭环系统 (LK001~LK005, SK002, SK003, SK005, TC002)
   - 代码工程与跨平台规范 (EN001~EN006, PL001)
   - 安全防线与只读原则 (SEC001~SEC005, SF005, SF006)
   - 运行时动态与抗破坏能力 (SF001, SF002, SF003, CK001, SF007, DY001~DY003)
4. **缺陷诊断处方与治理清单 (Prescriptions)**：按 `P0 阻塞` / `P1 缺陷` 逐条列出实测证据与最小修复处方；
5. **流水线进度与后续行动指南 (Pipeline Navigation)**：当前阶段状态与结案/推进选项。

### 标准分层事实卡规范（Fact Card Template）

所有模式下交付成果均统一输出分层量化基线事实卡（用客观指标说话）：

| 层级 | 检查项 | 实测值 | 正常基线 | 状态判定 |
|---|---|---|---|:---:|
| **L1 静态门禁** | audit.py 50+ 规则扫描 | 38 OK / 0 FAIL | 0 FAIL, 0 阻塞 | 🟢 PASS |
| **L2 动态验证** | selftest / evals 回归与负向拦截 | 全部 checks PASS | 100% 通过且真实拦截坏样本 | 🟢 PASS |
| **L3 成熟演进** | SEI 技能进化指数量化打分 | 100 / 100 | ≥ 85 分（工业级成熟） | 🟢 PASS |

#### 🧭 流水线进度与下一步指引规范（Pipeline Navigation）

在交付事实卡与报告后（特别是阶段 1 断点结案时），必须附带流水线阶段状态表与下一步明确指引，消除用户状态迷茫：

| 阶段编号 | 阶段名称 | 执行状态 | 核心产物 / 动作 |
|---|---|:---:|---|
| **阶段 1** | 全方位现状诊断（只读体检） | 🟢 **已完成** | 公开交付《技能全方位体检与质量检测报告》，排查静态与动态门禁 |
| **阶段 2** | 方案设计与多源对标挖掘 | ⏳ *待推进* | 12 组立体检索、深度穿透精读、冷门长尾探索池、避坑库落盘 |
| **阶段 3** | 处方施工与结构治理 | ⏳ *待推进* | 消灭弱引用、添加物料断言、注入测试脚手架、Zero-Mutation 解耦 |
| **阶段 4** | 闭环回归与终审验收 | ⏳ *待推进* | 全量自测与评测回归、Baseline 差分对比、清除临时副产物纯净交付 |

- **结案选项**：若仅需体检/诊断报告，告知用户当前已圆满完成；
- **进阶选项**：若需推进迭代优化，明确提示用户可直接回复指令（如「`继续阶段 2`」或「`推进多源对标挖掘`」）。
