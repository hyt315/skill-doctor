## 一、五大架构形态判定与自适应考量（Step 0）

在审查或进化启动前，首先判定被测技能所属的架构形态，因材施教启用专属重点，**坚决不搞一刀切，坚决不强塞无意义空脚本**：

| 技能形态 | 典型特征 | 专属审查重点 | 进化重点与免测策略 |
|---|---|---|---|
| **1. 纯提示词 / 认知指导型 (PROMPT)** | 零脚本，仅 `SKILL.md` + `references/` + `evals/` | 严查 Prompt 膨胀率与硬指令词密度（`TC002` ≤15 处）；输出 Schema 结构化约束；反幻觉负向边界 | **绝不强塞空脚本！** 工具化考核自适应切换为「输出 Schema + Few-Shot」，回归验证以 `evals/` 评测集与反例用例为主 |
| **2. CLI / 工具增强型 (CLI)** | 带 `scripts/`（Python / PowerShell / Bash） | 跨平台路径（`PL002`）、LF 换行（`PL001`）、`set -euo pipefail`（`EN005`）、退出码语义（`SF003`）、零外部依赖（`EN004`） | 纯标准库实现；支持 `--json` 机读与控制台只读；健全 `selftest.py` 与破坏夹具 |
| **3. MCP / 协议生态端型 (MCP)** | 含 MCP JSON 配置或 API 桥接 | Tool 定义与 Schema 规范；`stdio`/`sse` 模式；环境变量安全读取（`SEC003`）；Token 凭据脱敏 | 接口健壮性、超时熔断与错误码标准化 |
| **4. 多阶段流水线型 (PIPELINE)** | 含状态机（如 `stages/sN.md`、状态文件） | 路由器+阶段卡模式；阶段自证逻辑；状态落盘机制；断点恢复与回滚能力 | 状态持久化、幂等执行与死循环防御 |
| **5. 复合型 (HYBRID)** | 脚本工具 + 深度知识库/评测集复合体 | 兼顾确定性脚本执行（只读无损）与提示词认知工程，要求 AST 解析与破坏夹具双闭环 | 全要素工程化：脚本工具化 + 知识事实卡 + 自动化回归套件 |

## 二、审查体检核心工序

### 1. 审查四件套实操
- **静态口径对齐**：`audit.py` 覆盖结构、引用、资产、静默失效、安全、跨平台等 50+ 规则。重点核对三方口径一致性：`SKILL.md` 承诺的 ↔ `scripts/` 实现的 ↔ `references/` 描述的；
- **动态实跑**：真跑技能声称的验证命令（`audit.py --dynamic`）。结论只认三者一致：**退出码 (rc=0) + 末行 RESULT + 产物落盘**，任何矛盾均判定为坏门；
- **负向破坏夹具（DY002）**：对被审技能声称的“硬门”，故意构造破坏样本验证其是否真正拦截：
  - *文件齐全门*：故意抽掉必需产物；
  - *内容质量门*：构造超限/畸形内容；
  - *一致性门*：篡改协同字段之一；
  - *新鲜度门*：更新上游而不重跑下游；
  - *回读门*：提交后篡改关键数据。
  - **判定标准**：坏样本下门必须报错且以非 0 状态退出；若放行通过，直接判定为静默失效致命缺陷；
- **坑库对照**：逐条核验 `references/坑库.md` 中的 50+ 项实战踩坑。

### 2. 大改安全验证流程（治疗流程）
对技能做结构性重构或治疗时，严格遵循防退化 7 步法：
1. **沙箱先行**：复制至独立临时目录操作，不污染正式环境；
2. **基线回归**：改动前跑全套自测记录基线状态；
3. **内容锚点对账**：重构搬迁前后，用功能关键词 grep 新旧组合逐一核对；
4. **三重回归 + 差分对比**：改后重跑全部回归，结果须与基线同绿；
5. **全链演练**：跑最小真实任务验证全链路；
6. **逐字节确认后合并**：确认无误后同步回正式目录；
7. **病例归档**：将新发现的缺陷沉淀回 `references/坑库.md`。

### 3. 弱引用与空头支票的最佳治理处方（Prescription Patterns）

针对审查中高发的「弱引用（LK005）」与「空头支票跳步（SF007）」，提供标准化代码级改造模式：

#### (1) 弱引用改造模式：行内动作指令（Inline Action Directives）
- **反例（弱引用/易被 AI 忽略）**：
  ```markdown
  ### 阶段 1：排查
  执行诊断排查。如果需要，可参考 `references/故障手册.md`。详见官方规范。
  ```
- **正例（行内动作化/不可绕过）**：
  ```markdown
  ### 阶段 1：排查
  - [ ] 1. 运行核心诊断命令：
        👉 动作：执行 `python scripts/diag.py --check`
  - [ ] 2. 匹配并分析深水区故障：
        👉 动作：读取 `references/故障手册.md`，比对当前错误码对应的排查对策
  ```

#### (2) 空头支票改造模式：硬锁产物门禁（Artifact Gating）
- **反例（声明式空头支票/易脑补跳步）**：
  ```python
  # 仅打印建议或要求大模型自律，大模型容易在回复中假装执行而跳步
  def plan_research():
      print("请务必使用 search_web 搜索以下关键词并阅读权威规范：...")
  ```
- **正例（工单落盘 + 强制机器门禁）**：
  ```python
  # 生成必须落盘的任务锁工单，后续阶段强行阻断未完成任务
  def plan_research(output_dir):
      task_lock = {
          "status": "AWAITING_SEARCH_AND_PITFALLS",
          "required_artifacts": ["references/domain-pitfalls.md"],
          "queries": ["..."]
      }
      lock_file = Path(output_dir) / ".doctor" / "research-task.json"
      lock_file.parent.mkdir(parents=True, exist_ok=True)
      lock_file.write_text(json.dumps(task_lock, indent=2, ensure_ascii=False), encoding="utf-8")
      print(f"🔒 已生成硬锁任务工单：{lock_file}。后置步骤必须检测产物落盘方可解锁。")
  ```

## 三、五阶段进化工程范式

```text
[阶段 1: 深水区挖掘] --> [阶段 2: 工具化升维] --> [阶段 3: 只读治理解耦] --> [阶段 4: 代理验证器] --> [阶段 5: 发布治理]
 (RFC/杀手坑/标杆)      (Scripts + 事实卡)       (Zero-Mutation 纪律)     (AST + 负向破坏夹具)      (零污染 + 纯粹日志)
```

### 1. 阶段一：领域深水区联网检索矩阵挖掘（核心质变）
拒绝闭门造车与浅层修补，通过 `evolve.py --research-plan` 提取关键词并调用联网工具执行四维检索：
- **维度 1：底层原理与权威规范 (RFC & Specs)**：官方标准通信协议、内核原理，确立分层诊断依据；
- **维度 2：生产级故障与深水杀手坑 (Killer Pitfalls)**：挖掘高频故障、竞态死锁与暗坑，沉淀至 `references/<domain>-pitfalls.md`；
- **维度 3：顶级开源标杆 (Top OSS Repos)**：检索同领域 5k+ Stars 开源项目的架构设计、Banner 门面与排版；
- **维度 4：客观指标基线与事实卡 (Metric Baselines)**：权威量化阈值区间，为技能注入标准分层 Fact Card。

### 2. 阶段二：工具化升维与事实卡解耦
- **核心路由器 (`SKILL.md`)**：严控在 2000 tokens 内，仅保留目标、架构、路由表与环境声明；
- **确定性工具 (`scripts/`)**：纯 Python 标准库实现，零外部依赖，标准退出码语义；
- **分层事实卡 (`references/`)**：配置手册、错误码对照表拆解为单层直达 Markdown，按需加载。

### 3. 阶段三：只读与治理解耦铁律 (Zero-Mutation)
- **只读默认**：体检、诊断、审查全流程 100% 只读，严禁擅自修改文件、配置或服务；
- **治理解耦与显式授权**：修复动作独立拆分，提供 Dry-Run 预检清单，**必须经用户明确授权后手动执行**；
- **快照与回滚**：高危治理必须提供原始状态快照与秒级回滚流程。

### 4. 阶段四与五：代理验证器与发布治理
- **静态 AST 安全解析**：静态扫描危险调用（裸 `eval`、宽捕获吞异常）与跨平台路径；
- **工程卫生与纯粹日志**：测试副产物（`audit-report.txt` 等）发版前物理清除；Commit 与 Release Notes 严格只记录功能优化与缺陷修复，严禁混入审查元过程。

## 四、形态自适应的技能进化指数（SEI）评估矩阵

SEI 为 100 分量化成熟度模型，由 `scripts/evolve.py` 自动计算并自适应加权：

| 评估维度 | 满分 | CLI / HYBRID / MCP / PIPELINE 考核重点 | 纯提示词型 (PROMPT) 自适应考核重点 |
|---|---|---|---|
| **1. 架构完备度** | 20 | `SKILL.md` (5) + `references/` (5) + `scripts/` (5) + `tests/` (5) | `SKILL.md` (10) + `references/` (5) + `evals/` (5)（零脚本不扣分） |
| **2. 工具/指令工程** | 20 | 原生脚本无第三方依赖 (10) + 机读输出支持 (10) | 结构化输出 Schema (10) + Few-Shot (5) + 反幻觉负向边界 (5) |
| **3. 事实卡工程** | 20 | 标准分层事实卡表格（检查项、实测值、基线、判定） (20) | 标准分层事实卡表格（检查项、实测值、基线、判定） (20) |
| **4. 安全与只读** | 20 | Zero-Mutation 只读优先 (10) + 治理须用户显式授权 (10) | Zero-Mutation 无破坏声明 (10) + 建议须用户确认/免责边界 (10) |
| **5. 自动化验证** | 20 | 回归套件 (10) + 破坏性负向夹具 (5) + 语法 AST 校验 (5) | `evals/` 评测集 (10) + 对抗性输入/反例边界测试样本 (10) |

### 成熟度评级
- **成熟级 (85 - 100 分)**：工业级成熟技能，形态契合度高，工具/提示词与自测闭环完备；
- **进阶级 (60 - 84 分)**：框架健全，需补强破坏负向夹具、深水区踩坑库或量化事实卡；
- **雏升级 (< 60 分)**：结构缺失严重，缺乏约束、评测集或基础多文件解耦。
