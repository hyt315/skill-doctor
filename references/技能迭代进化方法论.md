# 技能迭代进化方法论

本方法论确立了 AI Agent 技能从「单次编写」走向「可持续迭代进化」的标准化工程范式。涵盖从领域深水区挖掘、工具化升维、只读与治理解耦、代理验证器到发布治理的全生命周期。

## 一、五阶段进化范式总览（Evolution Paradigm）

传统技能开发往往停留在「写一段提示词让模型直接回答」，极易出现幻觉率高、跨环境失效、执行缺乏保证、难以自动化测试等问题。技能迭代进化引擎通过以下五阶段将技能升维为工业级系统：

```text
[阶段 1: 深水区挖掘] --> [阶段 2: 工具化升维] --> [阶段 3: 只读治理解耦] --> [阶段 4: 代理验证器] --> [阶段 5: 发布治理]
 (协议/标准/排障树)     (Scripts + 事实卡)       (Zero-Mutation 纪律)     (AST + 负向破坏夹具)      (零污染 + 干净日志)
```

## 二、阶段一：领域深水区检索与四维知识矩阵挖掘（Knowledge Mining）

### 1. 核心目标：从“浅层修补”到“灵魂注入”
把一个技能从「平庸/脆弱」提升到「工业级卓越」，最关键的质变**绝非改改标点或修修换行，而是通过深度联网检索，挖掘该领域的官方规范、生产级杀手踩坑与开源标杆，从而对技能进行实质性的“内容丰满与灵魂注入”**。

### 2. 四维深水区联网检索矩阵（由 `evolve.py --research-plan` 自动生成）
- **维度 1：底层原理与权威规范 (RFC & Specs)**
  - 检索 Query：`<domain> RFC specification official documentation architecture internals`
  - 目标：检索官方标准规范、底层通信协议或内核原理，确立严谨的技术术语体系与分层诊断依据。
- **维度 2：生产级故障与深水杀手坑 (Killer Pitfalls)**
  - 检索 Query：`<domain> production outage common pitfalls failure modes edge cases race condition`
  - 目标：挖掘生产环境中导致静默失败、排查死循环的杀手级坑，沉淀至 `references/<domain>-pitfalls.md`。
- **维度 3：GitHub 顶级开源标杆 (Top OSS Repos)**
  - 检索 Query：`<domain> site:github.com top stars best practices tools banner readme`
  - 目标：参考同领域 5k+ Stars 明星开源项目的工程架构、Banner 视觉风格、输出排版与核心设计。
- **维度 4：客观指标基线与事实卡 (Metric Baselines)**
  - 检索 Query：`<domain> performance baseline normal metrics benchmark latency threshold`
  - 目标：提炼权威量化基线与健康度阈值区间，为技能注入高可信的标准分层 Fact Card。

### 3. 产出形式与资产沉淀
- 沉淀为 `references/` 下的结构化知识卡（如指标阈值速查卡、故障排查树、真实避坑指南）；
- 在 `SKILL.md` 中提炼规范标准事实卡（Fact Card），并在按需引导加载。

## 三、阶段二：工具化升维与事实卡工程（Multi-File Bundling & FactCards）

### 1. 核心目标
将庞大臃肿、容易产生注意力衰减与漂移的提示词拆解，升维为「确定性可执行脚本」与「单层直达事实卡」。

### 2. 三层解耦架构
- **第一层：`SKILL.md` 核心路由器（≤ 5000 tokens）**：
  - 仅保留核心目标、架构全景、执行工作流路由表与环境依赖声明；
  - 严控硬指令密度（避免滥用“必须/绝不”导致 IFScale 遵循率衰减）；
  - 建立对 `references/` 与 `scripts/` 的强引导指针（指明确切的触发时机与条件）。
- **第二层：`scripts/` 确定性工具（Zero-External-Dependencies）**：
  - 将所有具备确定性计算、正则解析、系统探测、指标采集的能力沉淀为独立 Python / Shell 脚本；
  - 坚持纯标准库实现，确保在纯净环境秒开秒跑；
  - 保证 Shebang、标准退出码语义（0=通过, 1=拦截, 2=配置错误）。
- **第三层：`references/` 事实卡（FactCards）**：
  - 将大段配置参数、命令清单、错误码对照表抽离为单层直达的 Markdown 事实卡；
  - 保证仅在需要该知识的具体阶段按需载入，大幅节约上下文窗口。

## 四、阶段三：只读与治理解耦铁律（Zero-Mutation & Authorization Boundary）

### 1. 核心目标
杜绝任何未经明确授权的破坏性操作，保证审计、诊断与体检全流程对目标系统 100% 只读。

### 2. 铁律准则
- **只读默认（Zero-Mutation by Default）**：
  - 检查、诊断、体检脚本在默认执行模式下，严禁删除文件、修改系统配置或重启服务；
  - 任何检测脚本产生的结果统一通过标准输出（stdout）或只读报表呈现。
- **治理解耦与明确授权（Remediation Decoupling）**：
  - 治理修复动作必须与只读诊断完全解耦，放在独立的修复脚本或由 `--fix` / `--remediate` 参数显式触发；
  - 在执行实质性更改前，必须明确向用户汇报待更改清单（Dry-Run 模式），获得交互确认或明确参数授权后方可执行。
- **状态快照与回滚机制（Snapshot & Rollback）**：
  - 高危治理动作必须在修改前持久化保存原始状态快照；
  - 提供反向撤销/回滚流程或脚本，确保治理失败可秒级恢复。

## 五、阶段四：代理验证器与负向破坏用例（Surrogate Verifier & Negative Fixtures）

### 1. 核心目标
杜绝只测正常路径的「假性全绿」测试套件，建立高可靠度的代理验证闭环。

### 2. 验证器工程标准
- **静态 AST 与语法安全校验**：
  - 自动解析被测技能的所有 Python/Shell 脚本，检测语法错误与 AST 结构合规性；
  - 检查是否存在危险函数调用（如裸 `eval()`、未经验证的 `os.system()`）与宽捕获吞异常（`except Exception: pass`）；
  - 检查跨平台换行符（CRLF 拦截）与绝对路径泄露。
- **正向基线验证（Happy Path）**：
  - 校验标准合法输入下，各个工具均能正常运行并退出码为 0；
  - 校验 stdout 输出遵循 `RESULT PASS` 格式约定。
- **负向破坏夹具（Negative Destruction Fixtures, DY002）**：
  - 故意构造畸形输入、缺失必需文件、越权操作、数据损坏、格式错误的负向样本；
  - 断言各个硬门与工具**必须**拦截违规样本，并以非 0 状态退出；
  - 若输入违规但脚本依然退出 0 报通过，直接判定为「静默失效」致命缺陷。

## 六、阶段五：发布治理与工程卫生（Clean Release & Engineering Hygiene）

### 1. 核心目标
保障开源仓库的整洁度、可维护性与发布日志的纯粹性。

### 2. 工程卫生规范
- **临时调试副产物即时清理**：
  - 审查产生的 `audit-report.txt`、测试产生的临时夹具、调试抓包文件等，在测试验证完毕后必须立即清理；
  - 严禁将临时产物随代码变更提交至 Git 仓库。
- **纯粹变更日志纪律（Pure Changelog Rule）**：
  - `CHANGELOG.md`、Git Commit Message 与 GitHub Release Notes 必须严格只记录**优化了什么、增加了什么功能、修复了什么问题**；
  - 严禁在对外日志中记录内部审查工具名称、提示词设计痕迹或元过程评价。

## 七、形态自适应的技能进化指数（SEI）评估矩阵

SEI 是一套满分为 100 分的技能成熟度量化指标体系，由 `scripts/evolve.py` 自动化计算。**针对不同架构形态实行自适应考核，坚决不强塞无意义脚本**：

| 评估维度 | 满分 | CLI / HYBRID / MCP / PIPELINE 考核重点 | 纯提示词型 (PROMPT) 自适应考核重点 |
|---|---|---|---|
| **1. 架构完备度 (Architecture)** | 20 | `SKILL.md` (5) + `references/` (5) + `scripts/` (5) + `tests/` (5) | `SKILL.md` (10) + `references/` (5) + `evals/` (5)（零脚本不扣分） |
| **2. 工具/指令工程 (Tooling / Schema)** | 20 | 可执行原生脚本无依赖 (10) + `-Quick/-Json` 只读机读支持 (10) | 结构化输出 Markdown/JSON Schema (10) + Few-Shot 示例 (5) + 反幻觉负向边界 (5) |
| **3. 事实卡工程 (FactCard)** | 20 | 标准分层事实卡表格（检查项、实测值、正常基线、状态判定） (20) | 标准分层事实卡表格（检查项、实测值、正常基线、状态判定） (20) |
| **4. 安全与只读 (Safety)** | 20 | Zero-Mutation 只读优先声明 (10) + 治理须用户明确授权 (10) | Zero-Mutation 无破坏声明 (10) + 建议须用户确认/免责边界 (10) |
| **5. 自动化验证 (Verification)** | 20 | `selftest.py` / `tests/` 回归套件 (10) + 破坏性负向夹具 (5) + 语法 AST 校验 (5) | `evals/` 评测集 (10) + 对抗性输入/反例边界测试样本 (10) |

### 成熟度评级
- **成熟级 (85 - 100 分)**：工业级成熟技能，形态与定位高度契合，工具化/提示词工程与验证闭环健全；
- **进阶级 (60 - 84 分)**：功能良好技能，具备基本框架，需针对性补强负向反例、深水区踩坑库或事实卡基线；
- **雏升级 (< 60 分)**：结构缺失严重，缺乏输出 Schema 约束、评测集或基础多文件解耦。
