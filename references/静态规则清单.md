# 静态规则清单

audit.py 静态检查的规则依据。规则码沿用 skilllint 分类学，指标融合 Anthropic 官方规范、agentskills.io 开放标准、MiniMax 官方规范与 GitHub 2026 工业级工程实践。

级别：ERROR = 审查不通过必须修；WARN = 建议修，不阻断；INFO = 辅助信息提示。

豁免：行尾 `# skill-doctor: allow`（附理由）豁免该行；`skill-doctor: allow-block 规则码`（写在文件内任意位置，不带码=豁免整文件）豁免文件级启发式规则（SF002/SF005/SF006/SEC002/SEC004/PL001），仅用于正则字面量等确证误报。

## A 结构合规（FM/SK）

| 规则码 | 级别 | 规则 | 出处与核心价值 |
| --- | --- | --- | --- |
| **FM001** | ERROR | `SKILL.md` 存在且是目录内唯一入口（子目录再出现 SKILL.md 会造成嵌套技能误识别）。`工作区/`、`workspace/` 内的有意嵌套技能豁免 | 实战教训：嵌套技能会被宿主误认成主入口 |
| **FM002** | ERROR | frontmatter 存在（`---` 包裹的 YAML 头） | skilllint FM001；agentskills.io |
| **FM003** | ERROR | `name` 字段存在，匹配 `^[a-z0-9]+(-[a-z0-9]+)*$`，≤64 字符，与目录名一致 | agentskills.io 规范；MiniMax validate_skills.py |
| **FM004** | ERROR | `description` 字段存在，≤1024 字符 | agentskills.io 规范 |
| **FM005** | WARN | frontmatter 可选字段合法性：`compatibility` ≤500 字符；`allowed-tools` 为空格分隔、不含逗号；`license`/`metadata` 非空 | agentskills.io 规范：compatibility 上限 500；allowed-tools 空格分隔 |
| **FM006** | ERROR | `name` 不含保留字 anthropic/claude（平台会拒收或误识别） | Anthropic 官方：保留字禁令；anthropics/skills 2026 实证改名 |
| **FM007** | ERROR | `name`/`description` 不含 XML 尖括号（防注入系统提示） | Anthropic 官方；himself65/skill-lint claude 模式 |
| **FM008** | WARN | `description` 用第三人称（"Processes Excel..."），不用第一人称（"I can help..."） | Anthropic best practices：描述始终第三人称 |
| **SK001** | WARN | description 含"何时触发"信息（出现"当/时/使用时机/Use when/Use for/invoke/适用于"类触发词），纯功能描述会导致欠触发 | Anthropic best practices：描述要含做什么+何时用 |
| **SK002** | WARN | SKILL.md 正文 <500 行；超限应拆分到 references/ | Anthropic best practices |
| **SK003** | WARN | 引用文件一层深（SKILL.md 直接引用的文件，不得再套引用第三层）；>100 行的参考文件头部应有目录 | Anthropic best practices |
| **SK004** | WARN | 全目录仅一个 SKILL.md（FM001 的全树版） | 实战教训 |
| **SK005** | WARN | SKILL.md 正文 token 估算 <5000（CJK 字符按 1 token、其余按 4 字符 1 token 粗估）；超限会挤占上下文 | Anthropic/agentskills.io：指令 <5000 tokens；skilllint SK006/TC001 |

## B 引用与资产完整性（LK/AS）

| 规则码 | 级别 | 规则 | 出处与核心价值 |
| --- | --- | --- | --- |
| **LK001** | ERROR | SKILL.md 引用的相对路径文件全部存在（markdown 链接、行内代码路径逐个核对） | skilllint LK001；引用不存在文件时 Agent 会幻觉内容 |
| **LK002** | ERROR | 文档中出现的脚本名/命令真实存在（文档说"跑 scripts/xxx.py"则该文件必须在） | 实战教训：文档承诺校验但脚本无实现 |
| **LK003** | WARN | scripts/ 目录里的文件都被文档提及或被其他脚本调用（孤立脚本=死代码或文档漏写用法） | MiniMax 规范：脚本用法要写在 SKILL.md 或参考文件 |
| **LK004** | WARN | references/ 下所有 .md 文件均被 SKILL.md/其他 references/脚本提及（孤儿文件=加载不到的 token 浪费） | claude-skill-lint 图分析；references 按需加载，未链接=永不加载 |
| **LK005** | WARN | SKILL.md 对每个 references/ 文件的引导须含明确读取时机（必读/先读/逐条对照/When/If you need 等）；只有"详见/可参考"类弱措辞=AI 不会主动读 | agentskills.io：references loaded only when required；官方 skill-creator 规范 |
| **AS001** | ERROR | Markdown 链接引用的本地资产（图片、视频、演示文件）必须在盘存在（防 README/文档断图断链） | 2026 多模态技能规范：引用资产必须在盘 |
| **AS002** | WARN | `assets/` 目录中无 >10MB 且未被文档引用的孤儿超大文件（防无意膨胀 git 仓库） | 2026 工程实践：资产按需打包 |

## C 静默失效扫描（SF）

| 规则码 | 级别 | 规则 | 出处与核心价值 |
| --- | --- | --- | --- |
| **SF001a** | ERROR | Python 脚本无裸 `except:` / `except Exception:` 后接 pass/continue（宽捕获吞一切=门放行） | 实战教训：静默失效家族 |
| **SF001b** | WARN | 窄类型 `except XxxError:` 后接 pass/continue（回退可能合理，须人工确认回退不弱化门） | 实战教训：合理回退必须有告警留痕 |
| **SF002** | WARN | 输出含 "skipped"/"忽略"/"跳过" 且无告警升级的代码路径（静默跳过要打 WARN 以上日志） | 实战教训：figure not found, skipped |
| **SF003** | WARN | 校验脚本退出码语义正确（FAIL 必须 rc≠0；rc=0 但打印 FAIL 的脚本是坏门） | 实战教训：回读硬门外置校验的教训 |
| **SF004** | WARN | 可选回退路径有告警（"playwright 缺失则跳过截图"类逻辑必须留痕）。人工检查 | 实战教训：无 playwright 回退 |
| **SF005** | WARN | 脚本无危险动态执行：`eval(`/`os.system(`/`subprocess` + `shell=True`/`curl|bash` 管道 | 华为上架规范；Snyk ToxicSkills；NVIDIA SkillSpector |
| **SF006** | WARN | Python 脚本无交互提示 `input(`（agent 非交互 shell 会挂死） | agentskills.io using-scripts：禁止交互式提示 |

## D 深度安全与防泄露（SEC）

| 规则码 | 级别 | 规则 | 出处与核心价值 |
| --- | --- | --- | --- |
| **SEC001** | ERROR | 无硬编码密钥（`sk-[a-zA-Z0-9]{20,}`、`AKIA[0-9A-Z]{16}`、`Bearer xxx`、token 实值）。tests/fixtures 夹具降级 WARN | MiniMax validate_skills.py；防泄露铁律 |
| **SEC002** | WARN | 无绝对个人路径（`C:\Users\`、`/home/` 出现在非示例上下文） | 实战教训：交付泄露本机开发环境路径 |
| **SEC003** | WARN | 脚本读凭据走环境变量或 `.private/` 类目录，且该目录在 `.gitignore` | MiniMax 规范 |
| **SEC004** | ERROR | 无 Git 内嵌 Token URL（如 `https://ghp_xxx@github.com`、`https://<token>@`） | 2026 实战教训：远程推送脚本泄露敏感 PAT |
| **SEC005** | WARN | 无开发机私有会话标记与临时体检报告残留（如 `audit-report.txt` 提交进 git） | 保持仓库 100% 纯净与生产安全 |
| **SEC006** | WARN | 无提示词注入攻击向量与系统指令未转义模拟 | 2026 LLM 安全规范：防 Prompt 注入与提权 |

## E 脚本与跨平台工程（EN/PL）

| 规则码 | 级别 | 规则 | 出处与核心价值 |
| --- | --- | --- | --- |
| **EN001** | WARN | Python 脚本有 shebang 行（`#!/usr/bin/env python3`） | MiniMax 规范 |
| **EN002** | WARN | 脚本失败时给清晰错误信息而非裸 traceback | MiniMax 规范 |
| **EN003** | WARN | 所有文件 UTF-8 编码（不含 UTF-16 BOM `ÿþ` 开头的文件） | 实战教训：PowerShell 重定向 UTF-16 |
| **EN004** | INFO | 依赖情况登记（scripts/ 带 requirements.txt 或文档声明零依赖） | MiniMax 规范 |
| **EN005** | WARN | bash 脚本含 `set -euo pipefail`（缺失则管道中间失败被静默吞掉） | 社区评审必纠项：脚本失败返回 0 误判成功 |
| **EN006** | FAIL | 所有 md 资源文件可按 UTF-8 解码且不含控制字符（`\x00` 等） | 实战教训：NUL 字节导致宿主拒读 |
| **EN007** | WARN | Node.js 启动器采用跨平台 `.mjs` 规范且具备跨平台 OS 判断 | 2026 跨平台规范：统一启动器 |
| **PL001** | ERROR | Bash 脚本不得含 Windows CRLF 换行符（`\r` 会导致 Linux CI 报 `command not found: set`） | 跨平台致命坑：Windows 下编辑 sh 脚本引发 CI 崩溃 |
| **PL002** | WARN | 脚本无硬编码跨平台路径拼接（强制推荐 `pathlib.Path` 或 `os.path.join`） | 跨平台兼容性保障 |
